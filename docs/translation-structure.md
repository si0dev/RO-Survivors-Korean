# 번역 데이터 관리 구조

## 구조와 기준

이번 개편의 기준은 main의 `fa0952e6a604f5556f707457d2d2a0ffaed68c49`이다. 기존 게임 빌드 `81defc1e6`, 관리 데이터 버전 `0.3.23`, 엔진 `0.4.12`는 변경하지 않는다. 서버 원문을 새로 추출하거나 번역을 재검수하지 않았다.

- `catalog.json`: 이전 두 파트의 메타데이터를 그대로 보존한다.
- `game-talents-fixed.json`: 본편·특성 공용 언어 테이블의 고정형.
- `game-talents-variable-a.json`, `game-talents-variable-b.json`: 공용 언어 테이블의 가변형. 파일 크기 관리를 위해 ID 첫 16진수 0–7, 8–f로 구분한다.
- `wiki-fixed.json`, `wiki-variable.json`: `scope: wiki` 레코드의 고정형·가변형.
- `news.json`: 과거 및 최신 소식의 기존 승인 레코드.
- `common.json`: 근거가 확인된 동일 명칭의 공통 한국어 값. 원문 ID별 레코드 및 원문 해시는 별도로 유지한다.

본편과 특성 페이지는 같은 언어 테이블과 ID 체계를 이용하므로 각 화면의 실제 사용처를 확정할 수 없는 레코드를 임의로 분리하지 않는다. 위키는 원문 해시로 조회한다. 소식은 기존 최신 공개 소식 검사 정책을 유지하고 과거 소식도 기존 번역을 보존한다. 레거시 실행 사전은 이전에 제거되었으며, [기존 검수 기록](translation-audit-2026-11-25.md) 및 Git 이력을 그대로 보존한다.

각 관리 레코드의 분류(fixed/variable/news)는 파일명으로 복원하며, `reason`은 분류 근거, `positions`는 이전 base/extra의 삽입 순서(없는 경우 null), `record`는 기존 런타임 레코드다. 관리 파일에서 중복 `type`과 빈 `record.placeholders`만 생략한다. 읽을 때 분류와 빈 배열을 복원하며 기존 명시형 JSON도 읽을 수 있다. 공통 참조 및 비어 있지 않은 플레이스홀더는 그대로 저장한다. positions는 번역 원문 식별자가 아니며, 위키의 동일 해시 충돌 우선순위와 전체 JSON 순서까지 보존하기 위해 사용한다. 9개 동일 ID의 두 위치를 한 레코드에 보존한다. 승인 가져오기에서 positions를 자동 관리하며, JSON은 한 레코드 한 줄 형식으로 저장해 변경 이력을 읽기 쉽게 한다.

## 분류 근거와 공통화

고정형은 확인된 명칭 또는 안정적인 UI/능력치 명칭, 가변형은 효과·조건·규칙·설명 및 문맥 불확실 항목, 소식형은 기존 뉴스 추가 이력에 따른다. 숫자 포함 여부만으로 결정하지 않는다.

기존 레코드는 원문 ID와 SHA-256 해시, 한국어, 플레이스홀더(및 위키 scope)를 저장하며 원문 전체 또는 개별 화면 문맥을 저장하지 않는다. 해시로 원문을 복원하지 않았다. 새 관리 메타데이터는 원문 검증 상태가 아니다.

| reason | 근거 |
| --- | --- |
| history-name | 명칭 추가 전후 Git 데이터 차이 및 원문 해시 동일 확인 |
| history-news | 소식 추가 전후 Git 데이터 차이 및 원문 해시 동일 확인 |
| same-named-source | 확인된 명칭과 위키의 원문 해시·번역·변수가 동일 |
| stable-label | 명백한 고정 UI/능력치 용어의 한국어 값 |
| effect-or-condition | 기존 번역의 효과·조건·변수 표현 |
| insufficient-context | 원문/세부 문맥 부족으로 보수적 가변형 |
| import-name / import-news | 승인 가져오기에서 명시된 원문 종류 |

명칭 근거: `2f520318`(아이템 411), `b7afbb59`(스킬·몬스터 488), `019bc832`(카드 9), `251fdb4e`(카드 89). 소식 근거: `f96bed3c`(49), `83ea6007`(8).

공통화는 기존 리소스 명칭의 ID 및 원문 해시와 일치하고 한국어·플레이스홀더도 동일한 명확한 명명 문구, 또는 본편·위키의 기존 위스퍼 테스트 근거가 있는 경우에 한정했다. 일반 동음이의어, 다른 번역, 변수나 HTML이 포함된 명칭, 문맥 미확인 후보는 독립 저장한다. 공통 여부와 고정/가변 여부는 서로 독립적이다. 가변형 공통 참조도 데이터 구조상 가능하지만 이번 이관에서는 안전한 세부 문맥 근거 부족으로 강제 통합하지 않았다. 동일 해시만으로 의미가 같은 것으로 확정하지 않는다.

공통 번역의 `record.ko`는 `{"ref":"공통 ID"}`로 저장한다. 참조 대상은 원문 해시·플레이스홀더가 일치해야 하며, 두 개 이상의 서로 다른 영역의 사용처가 있어야 한다. 공통 한국어 값을 편집하면 의도된 참조 전체에 반영된다. 개별 원문이 변경되거나 개별 번역값을 바꾸면 가져오기 과정에서 그 참조만 분리한다. 남은 참조가 하나 또는 한 영역뿐이면 독립 레코드로 환원한다. 자동으로 새로운 공통 그룹을 추측해 생성하지 않는다.

2026-11-27 정리: 확인된 명칭 분류와 위키가 정확히 동일한 원문 해시·번역·플레이스홀더를 가진 217개 그룹을 추가로 공통화했다. 문맥이 모호한 일반 용어 및 다른 ID가 함께 존재하는 그룹은 제외했다. 두 기존 파트의 모든 레코드와 삽입 순서가 변경 전과 동일함을 전수 비교했다. 이후 빌드 `7c004f793`에서 통합 추출, 본편 런타임 추출(6,111개), 특성 런타임 추출(5,581개), 과거 공개 소식을 대조해 모든 범위에서 미관측인 본편 기록 5개를 제거했다. 남은 레코드 값·순서는 기존과 동일하다. `catalog.json`의 `retired`는 배포 시 삭제 승인용 ID 및 이전 원문 해시이며 런타임에 포함되지 않는다. 다른 ID 또는 해시의 삭제는 배포에서 거부한다. 다음 승인 가져오기에서 카탈로그를 재작성하면 이 일회성 필드는 제거된다.

2026-11-27 위키 최종 대조: 빌드 `7c004f793`의 20개 분류·72개 하위 탭, 1,885개 원문 전부 매칭, 미번역 0개. 미관측 8개 중 최신 원문으로 명확히 대체된 미니 보스/MVP 저항 설명, 저항 스킬 목록, 신 자동 선택 설명, 전염 효과 4개만 삭제 승인에 추가했다. 검색 결과 제목의 영어/스페인어 변형 2개는 회귀 테스트로 사용 근거가 확인되어 유지했다. 프론테라 사서 제목 및 솔져 스켈레톤·소희 드롭 문구는 미관측만으로 삭제할 수 없어 유지했다. 삭제한 ID 외 모든 기존 레코드 값·분류·공통 참조 및 상대 순서를 유지한다. 관리 JSON 전체는 2,587,888바이트에서 2,323,119바이트로 감소했다.

## 유지보수 및 기존 배포

기존의 승인 작업 목록 가져오기 명령을 사용한다. `tools/import.mjs`가 신규/변경 ID의 종류 및 번역 표현으로 분류하며, 동일 해시의 기존 분류는 보존한다. 기존에 원문이 없는 항목을 자동으로 검증 완료로 전환하지 않는다. 원문 ID·해시를 새로 해석하거나 파일 위치로 재생성하지 않는다. 명칭도 원문 변경 검사 대상이다. 추출 누락은 자동 삭제하지 않는다. 자동 추출의 `AUDIT` 및 `UNMATCHED` 로그는 현재 게임/특성/전체 공개 소식의 ID와 위키 원문 해시를 기존 승인 레코드와 각각 대조한 미관측 후보만 기록한다. 원문이 실제 삭제됐다는 증거가 아니며, 원본 게임 파일을 저장하지 않는다.

`tools/records.mjs`는 관리 자료를 읽어 이전 두 파트 및 기존 병합 순서를 복원한다. `npm test`, `npm run build`는 기존과 동일하며 `dist/ko.json`에는 관리 메타데이터나 참조를 포함하지 않는다. 런타임, 원문 식별/해시, 미번역 검사, 위키 조회, 소식 검사, UI, Tampermonkey URL, 기존 CI 배포 정책은 변경하지 않았다. 검증 단계에만 이전 파트가 부모 커밋에 있을 때 전수 이관 비교를 실행하는 검사를 추가했다. 기존 배포와 데이터 내용이 같으면 새 번역 또는 엔진 버전을 발행하지 않는 정책을 유지한다.

개편 기준 전수 비교는 기존 커밋이 로컬 Git 이력에 있을 때 다음 명령으로 재현 가능하다.

```sh
node tools/verify-structure.mjs fa0952e6a604f5556f707457d2d2a0ffaed68c49
```

이 명령은 이관 전후가 완전히 같아야 하는 시점에만 사용한다. 이후 승인된 번역 변경이 있으면 차이가 발생하는 것이 정상이다. 일반 자동 테스트는 현행 카탈로그의 구조와 회귀 동작을 검증한다.
